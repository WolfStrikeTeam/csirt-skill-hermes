# Laporan Tes: INC-002 (SSH brute force ke ns1)

Laporan insidennya (format laporan insiden resmi): [docs/incidents/INC-002.md](../incidents/INC-002.md).

Tes end-to-end Hermes + WOLFSTRIKE dengan dataset insiden nyata. Tujuannya cek dua hal: apakah alurnya jalan (Hermes bisa memanggil tool WOLFSTRIKE), dan seberapa banyak tool WOLFSTRIKE ikut menyumbang analisa.

**Tanggal tes:** 14–15 Nov 2026
**Hasil singkat:** alur jalan dan laporan akhir akurat, tapi hampir semua analisa datang dari model (GLM), bukan dari tool. `triage_incident` dan `map_mitre_attack` masih placeholder.

## Setup

| Komponen | Nilai |
|---|---|
| Agent | Hermes Agent v0.23.1, Windows native |
| Model | `glm-5.3-flash` lewat gateway OpenAI-compatible |
| MCP server | WOLFSTRIKE, `npm run dev` di `http://localhost:3000/mcp` |
| Skill Hermes | `incident-summary`, `threat-investigation`, persona `SOUL.md` |
| VirusTotal | Tidak dikonfigurasi |

## Dataset

Dataset lokal, tidak di-commit ke repo.

| File | Isi |
|---|---|
| `inc02-ns1-auth.log` | Auth log SSH host `ns1` (10.1.2.10), 3.162 baris, tanpa tahun, zona -0700 |
| `inc02-filerun-apache-access.log` | Access log web FileRun, 3.951 baris, 26 Sep 2023 -0700 |
| `inc02-network.pcap` | Capture jaringan 21,6 MB, UTC. Format pcap klasik (nama asli `.pcapng` keliru) |

Hermes dan WOLFSTRIKE tidak bisa membaca pcap. Temuan dari pcap dianalisa terpisah (script Python) lalu diberikan ke Hermes sebagai teks: `10.18.200.126` mengunduh `/shadow` dan `/FileRun_2017_09_18_PHP70.zip` dari `10.1.2.10:81`.

## Prosedur

Satu prompt ke Hermes (`hermes chat -q`) yang meminta:

1. Ringkas kedua log pakai pencarian (bukan baca utuh).
2. Panggil berurutan: `intake_incident` → `triage_incident` → `map_mitre_attack` → `extract_iocs` → `respond_and_report` dengan `executeBlock: false`.
3. Jangan panggil `validate_iocs`, `enrich_ioc`, `investigate_incident`: semua IP privat dan VirusTotal belum dikonfigurasi.

## Hasil

**Alur:** jalan. Durasi 7 menit 56 detik, 5 perintah shell (grep/awk, read-only), 7 pemanggilan tool. Log server mengonfirmasi kelima tool WOLFSTRIKE terpanggil dan tidak ada panggilan ke VirusTotal. Tidak ada yang diblokir.

**Kesimpulan Hermes** (cocok dengan analisa manual):

- Severity **CRITICAL**, keyakinan tinggi. Full root compromise + pencurian kredensial + pengambilan data.
- Penyerang: host internal `10.18.200.126`. Korban: `ns1` (`10.1.2.10`).

| Waktu (-0700) | Kejadian | Sumber |
|---|---|---|
| 03:14:27 | POST login FileRun pertama | access log |
| 03:15:45 | SSH brute force mulai (total 1.344 gagal `root`, 360 gagal `ubuntu`) | auth log |
| 03:18:54 | **Login SSH sukses** sebagai `ubuntu` (#1) | auth log |
| 03:19–03:27 | Brute force login FileRun, 3.936 POST (~9/detik), semua HTTP 200 | access log |

MITRE ATT&CK (dipetakan oleh model, bukan oleh tool): T1110.001, T1078.003, T1548.003, T1059.004, T1003.008, T1074.001, T1048.

Hermes juga mencatat hal yang belum bisa dipastikan, antara lain: `/shadow` terunduh (03:25) sebelum `http.server` tercatat di sudo log (03:29:25), dan sukses/gagalnya brute force FileRun tidak bisa dibuktikan dari access log karena semua respons 200.

## Evaluasi tool WOLFSTRIKE

| Tool | Status | Temuan |
|---|---|---|
| `intake_incident` | Jalan | — |
| `triage_incident` | **Placeholder** | Selalu mengembalikan "Suspicious Activity", kill chain "C2 / Exploitation", TA0001 + TA0011. Severity hanya meneruskan input. |
| `map_mitre_attack` | **Placeholder** | Selalu mengembalikan T1059 saja, apa pun input-nya. |
| `extract_iocs` | Jalan, ada bug | `http.server` (dan sebelumnya `payload.exe`) terbaca sebagai domain. **Sudah diperbaiki**, lihat di bawah. |
| `respond_and_report` | Stub | Blokir belum terhubung ke firewall/EDR. Dengan `executeBlock: true`, laporan menulis `BLOCKED` padahal tidak ada yang diblokir. |
| VirusTotal client | Bug | Default `VT_API_KEY` berisi teks `"<VIRUSTOTAL_API_KEY>"`, jadi cek "key belum diset" tidak pernah jalan dan IOC tetap dikirim ke VirusTotal. |

> **Update setelah tes:** `triage_incident` dan `map_mitre_attack` sekarang mengembalikan `status: "not-implemented"` tanpa nilai karangan. Lihat [INC-001](INC-001.md#uji-konsistensi-3-run).

Artinya kualitas laporan sekarang bergantung penuh pada model. Dengan model yang lebih lemah, hasilnya akan turun jauh.

## Yang sudah diperbaiki

Branch `fix/ioc-domain-and-typecheck`:

- `extract_iocs` hanya menganggap token sebagai domain kalau TLD-nya ada di daftar IANA (bundled), atau suffix khusus: `.onion`, `.i2p`, `.bit`, suffix jaringan internal, dan nama special-use. Nama file dan potongan kode tidak lagi lolos.
- Env `WOLFSTRIKE_EXTRA_TLDS` dan `WOLFSTRIKE_TLD_CHECK`, script `npm run update-tlds`, dan GitHub Action mingguan untuk memperbarui daftar TLD.
- `npm run typecheck` sebelumnya gagal 11 error di `main`; sekarang 0.

## Yang masih terbuka

1. Implementasi nyata `triage_incident` dan `map_mitre_attack`.
2. `respond_and_report`: hubungkan ke kontrol blokir, atau ubah label `BLOCKED` supaya tidak menyesatkan selama masih stub.
3. VirusTotal client: hapus default placeholder `VT_API_KEY`, dan lewati IP privat (RFC 1918) saat validasi/enrichment.
4. Tidak ada tool untuk membaca file log atau pcap. Hermes harus meringkas log sendiri, dan pcap butuh tool terpisah.

## Cara mengulang

1. Jalankan `npm run dev` di root repo.
2. Pastikan Hermes terhubung: `hermes mcp test wolfstrike` harus menampilkan 8 tool.
3. Jalankan prompt di bagian Prosedur dengan `hermes chat -q '...'`, ganti path log sesuai lokasi dataset.
