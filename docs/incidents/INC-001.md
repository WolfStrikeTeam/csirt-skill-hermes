## 01. Executive Summary

Server WordPress `greek.spenlab.local` (`10.1.2.111`) menjadi sasaran reconnaissance dari dua host internal pada dua periode berbeda:

- **21 Mar 2020:** `10.18.200.87` memindai server dengan WPScan dan menjelajah secara manual: membuka `phpinfo`, directory listing, dan mengirim POST ke `xmlrpc.php`.
- **16 Jul 2018:** `10.18.200.26` mengenumerasi username, mencoba probe SQL injection, dan mengirim komentar yang diikuti error 500 di halaman depan.

**Tidak ada bukti server berhasil dibobol.** Severity **Medium**: tidak ada dampak yang terbukti, tapi server terekspos berat (software EOL, `phpinfo` terbuka, directory listing aktif), sehingga hasil recon ini bisa dipakai untuk serangan berikutnya.

## 04. Technical Investigation

**Attack vector:** akses HTTP ke aplikasi WordPress dari jaringan internal.

**Threat actor:** tidak diketahui. Dua host internal (`10.18.200.87`, `10.18.200.26`), selisih hampir 2 tahun. Tidak ada bukti keduanya aktor yang sama. Bisa juga pengujian resmi; belum dikonfirmasi.

**MITRE ATT&CK:**

| Status | Technique | Bukti |
|---|---|---|
| Terbukti | T1595.002 Active Scanning: Vulnerability Scanning | WPScan v3.7.7, 357 request |
| Terbukti | T1592.002 Gather Victim Host Information: Software | `info.php`, `readme.html`, versi plugin/tema |
| Terbukti | T1589 Gather Victim Identity Information | `?author=1` → 200 |
| Percobaan | T1190 Exploit Public-Facing Application | Probe `?p=14%27`, POST komentar, POST `xmlrpc.php`; tidak ada tanda berhasil |

**Indicators of Compromise:**

| Tipe | Nilai | Keterangan |
|---|---|---|
| IPv4 | `10.18.200.87` | Sumber scan dan eksplorasi (2020) |
| IPv4 | `10.18.200.26` | Sumber enumerasi dan probe (2018) |
| User-Agent | `WPScan v3.7.7 (https://wpscan.org/)` | Tool ofensif |
| User-Agent | `Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)` | Dipakai pada POST `xmlrpc.php`, kemungkinan palsu |

Bukan IOC: `wpscan.org` (bagian User-Agent), `127.0.0.1` dan `::1` (wp-cron dan koneksi internal Apache), `10.18.200.181` dan `10.18.200.211` (browsing normal).

**Affected hosts and systems:** `greek.spenlab.local` (`10.1.2.111`): WordPress 4.0.24, PHP 5.4.16, Apache 2.4.6 (CentOS).

**Malware analysis findings:** tidak ada malware atau webshell teramati di access log.

## 08. Root Cause Analysis

Recon berhasil memetakan server karena **konfigurasi dan software server membuka terlalu banyak informasi**:

- WordPress 4.0.24 dan PHP 5.4.16 sudah EOL.
- `info.php` (`phpinfo`) tertinggal dan bisa diakses publik.
- Directory listing aktif di `wp-content` dan `wp-includes`.
- `xmlrpc.php` aktif dan menerima POST anonim.
- Registrasi user tampak terbuka.
- Enumerasi username lewat `?author=N` tidak diblokir.

Tidak ada pencatatan pendukung (error log, audit log WordPress, body request), sehingga hasil POST ke `xmlrpc.php` dan komentar tidak bisa dipastikan.

## 09. Recommendations

**Jangka pendek:**

1. Jalankan tindakan di bagian 06 (pending approval).
2. Hapus `info.php`, matikan directory listing (`Options -Indexes`), nonaktifkan atau filter `xmlrpc.php`, tutup registrasi user, blokir `?author=N`.

**Jangka panjang:**

1. Upgrade WordPress, PHP, dan Apache ke versi yang didukung.
2. Aktifkan error log, audit log WordPress, dan WAF/ModSecurity agar body request tercatat.
3. Alert untuk User-Agent scanner, lonjakan 404, dan pola injeksi di URL (misalnya rule Wazuh 31103).
4. Kebijakan: pemindaian ke server internal wajib lewat persetujuan.

## 11. Lessons Learned

- **Deteksi terlambat:** pemindaian WPScan dengan User-Agent yang jelas tidak memicu alert apa pun.
- **Aktivitas kecil mudah terlewat:** analisa otomatis pertama melabeli `10.18.200.26` sebagai browsing normal karena fokus pada IP dengan request terbanyak. Setelah aturan cakupan per-IP ditambahkan ke skill, aktivitas itu tertangkap di 3 dari 3 run. Detail di [laporan tes](../testing/INC-001.md).
- **Log tidak rapi:** log berisi beberapa periode dan tidak urut waktu, menyulitkan analisa. Rotasi log dan pengiriman ke SIEM perlu diperbaiki.
- **Bukti tanpa catatan custody:** pengumpul awal dan hash saat pengumpulan tidak tercatat.
